GitHub Copilot をエージェント モードで使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。この作業はマシン上でリアルタイムに進みます。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をその場で確認できます。エディターを離れずに差分を確認し、個々の変更を受け入れるか却下するか選び、追加のプロンプトを送って作業を改善または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して受け入れます。
- セッションの途中でエージェントに指示し、高コントラスト モードに加えてライト モードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、高コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加したいとのことです。新しい会話を始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各ステップが表示されます。調べているファイル、実行しているコマンド、提案する編集などが確認できます。各ファイルの編集は差分と **Keep** / **Undo** コントロールとともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールして、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
   - **Keep** を選択して変更を受け入れます。
   - **Undo** を選択して変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツール呼び出しで許可を求められた場合 (ターミナル コマンドの実行など)、エージェントは一時停止し、**Allow** プロンプトを表示します。問題がないコマンドだけを許可してください。

5. エージェントが高コントラスト モードの実装を完了するまで待ちます。最後に、変更の概要が表示されます。

## エージェントにライト モードの追加を指示する

高コントラスト モードを追加できたら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは以前の作業に関するコンテキストを保持しています。変更したコンポーネント、スタイルの実装方法、設定をローカル ストレージに保存する方法などです。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を確認し、ライト モードの追加案を提案します。
3. 高コントラスト モードの場合と同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を使います。
4. エージェントの進め方が希望と異なる場合 (たとえば、好みではない方法でトグル UI をリファクタリングする場合)、チャット入力欄の隣にある **Stop** ボタンを選択して停止し、追加の指示を送ります。

> [!TIP]
> 進行中のセッションに指示するほうが、最初からやり直すよりも効率的です。追加のプロンプトを使って、変更の依頼 ("CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う")、方向の修正 ("3 つ目のトグルを追加せず、既存の設定パネルにライト モードを統合する")、作業範囲の拡張 ("両方のトグルにキーボード ショートカットも追加する") などを行えます。

## 変更内容をレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターン (ARIA 属性、キーボード ナビゲーション、セマンティック HTML、ローカル ストレージによる永続化など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視し、方向付けしました。ファイルの編集を確認して受け入れるか却下するかを選び、コンテキストを失わずに追加のプロンプトで作業を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を受け入れる、または却下する。
- 追加のプロンプトを使い、進行中のセッションに指示する。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが行った変更をレビューします。
